# Session 3 デモンストレーション

このディレクトリは、ワークショップ中の「デモンストレーション（Before & After）」スライドに合わせて、実際にAIエージェントの挙動の違いを実演するためのものです。

**「AIへの依頼文（プロンプト）は全く同じなのに、プロジェクトのルール管理方法によって、生成されるコードの品質やレビューの精度が劇的に変わる」** ことを実演できます。

## ディレクトリ構成

3段階の比較になっている。

- `without-skill/`：ルールが全く設定されていない、素のプロジェクト
- `with-md/`：`.agents/AGENTS.md` に全ルールを1ファイルに詰め込んだプロジェクト（巨大なルールブックの失敗例）
- `with-skill/`：`.agents/skills/` 配下に `architect` / `reviewer` / `tech-lead` の3つのSkillを役割ごとに切り出したプロジェクト

各ディレクトリには用途の異なる3つのデモスクリプトが用意されている。

- `run.sh`：機能実装のデモ（曖昧な指示から商品レビュー機能のバックエンドを実装させる）
- `run-review.sh`：コードレビューのデモ（`src/` 配下の実装をレビューさせる）
- `run-flow.sh`：一気通貫フローのデモ（`with-skill` では `tech-lead` Skillが実装・監査・修正を自律的に連続実行する）

## 実演手順

プレゼンターは、それぞれのディレクトリに移動し、目的に応じたスクリプトを実行して比較を見せる。

### 1. 【Before】ルールなしプロジェクト

```bash
cd without-skill
./run.sh
```

➡ AIは「とりあえず動く」ものの、コントローラーにDB操作などがベタ書きされた平凡なコードを生成する。

### 2. 【比較】巨大なAGENTS.mdプロジェクト

```bash
cd ../with-md
./run.sh
```

➡ 実行しているコマンドは【Before】と全く同じだが、`AGENTS.md` に定義された4層アーキテクチャのルールを常に読み込んだ状態で実装するため、構造化はされる。一方でルールが1ファイルに肥大化している弊害（コンテキスト逼迫やノイズ）は本編スライドで解説する。

### 3. 【After】Skillで役割分担したプロジェクト

```bash
cd ../with-skill
./run.sh          # architect Skillによる実装
./run-review.sh    # reviewer Skillによる専門レビュー
./run-flow.sh       # tech-lead Skillによる一気通貫フロー
```

➡ 実行しているコマンドは【Before】【比較】と全く同じだが、AIが自動的に該当するSkill（`architect` / `reviewer` / `tech-lead`）を遅延読み込みし、役割に特化した高品質な出力を行う。

## 注意事項

- 各スクリプトは `agy` コマンドで実際にエージェントを起動する。ネットワークやAPIキーの都合で実演が難しい場合は、事前に一度実行しておいた出力結果をスクリーンショット等で控えておくことを推奨する。

# エラーハンドリング統一規約

## 第1条：例外の階層構造

- すべてのカスタム例外は `AppError` を基底クラスとして継承してください。
- 例外クラスは以下の3系統に分類します。
  - `DomainError`: ビジネスルール違反（400系に対応）
  - `NotFoundError`: リソース不存在（404に対応）
  - `InfrastructureError`: DB・外部API起因の障害（500系に対応）

## 第2条：エラーレスポンスの統一フォーマット

- APIのエラーレスポンスは必ず以下のJSON構造で返却してください。

```json
{
  "error": {
    "code": "REVIEW_ALREADY_EXISTS",
    "message": "この商品にはすでにレビューを投稿済みです。",
    "details": []
  }
}
```

- `code` は `SCREAMING_SNAKE_CASE` の一意なエラーコードとし、エラーコード一覧表に必ず追記してください。
- スタックトレースやSQL文など、内部実装が推測できる情報をレスポンスに含めてはなりません。

## 第3条：握りつぶしの禁止

- `catch` ブロックで例外を捕捉した後、ログも出力せず再スローもしない「握りつぶし」は絶対に禁止します。
- 例外を変換して再スローする場合は、必ず元の例外を `cause` として保持してください。

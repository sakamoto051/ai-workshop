# テストコード作成規約

## 第1条：テストの必須化

- 新規に作成したusecase層・domain層のコードには、必ずユニットテストを同時に作成してください。
- テストのないプルリクエストはレビュー対象外とします。

## 第2条：テストの構造

- テストは `describe` / `it` を用い、`it` の説明文は「〜の場合、〜を返すこと」の形式で日本語で記述してください。
- 1つの `it` の中で検証する事柄は原則1つとし、Arrange-Act-Assert の3段構成を守ってください。

## 第3条：テストデータとモック

- infrastructure層への依存はすべてインターフェース経由でモック化してください。実DBに接続するユニットテストは禁止です。
- テストデータの生成にはファクトリ関数（例: `createTestReview()`）を用意し、各テストファイルでの手書きコピペを避けてください。

## 第4条：カバレッジ基準

- usecase層・domain層のブランチカバレッジは **80%以上** を維持してください。
- カバレッジを満たすためだけのアサーションなしテスト（いわゆる水増しテスト）は禁止します。

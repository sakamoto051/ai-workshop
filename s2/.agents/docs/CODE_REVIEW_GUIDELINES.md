# 【クオリティ保証】社内規約に基づくコードレビュー

当プロジェクトでは、一般的な構文エラーだけでなく、システム全体に致命的な影響を与える脆弱性を防ぐため、静的なセキュリティガイドラインを厳格に適用します。

## 🔍 必須アクション

コードのレビューを依頼された場合、必ず以下の手順を踏んでください。

1. **全規約ファイルをチェックリスト化**:
   以下の規約ファイルをすべて読み込み、記載されている全項目を照合対象としてください。
   - `.agents/docs/ARCHITECTURE_STANDARDS.md`
   - `.agents/docs/SECURITY_GUIDELINES.md`
   - `.agents/docs/TYPESCRIPT_GUIDELINES.md`
   - `.agents/docs/BUSINESS_LOGIC_GUIDELINES.md`
   - `.agents/docs/ERROR_HANDLING_GUIDELINES.md`
   - `.agents/docs/TESTING_GUIDELINES.md`
2. **規約違反の指摘**:
   もし1つでも違反している箇所があれば、**「🚨 当社のガイドライン第〇条に違反しています」**という形式で条番号を明示して指摘し、修正コードを提示してください。
3. **甘いレビューの禁止**:
   「コードはきれいです」「一見問題なさそうです」といった表面的なレビューは不要です。バグや仕様漏れを見逃して本番にデプロイされた場合、甚大な被害が発生することを肝に銘じてください。
4. **指摘の優先度付け**:
   指摘には `[Critical]` `[Major]` `[Minor]` のラベルを付け、Critical が1件でもあればレビュー結果を「差し戻し」としてください。

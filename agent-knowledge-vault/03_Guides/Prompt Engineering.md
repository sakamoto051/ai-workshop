# Prompt Engineering & AGENTS.md

## 📝 概要
AI エージェントに対するプロンプト設計は、従来の「一発のプロンプトで良いコードを出させる」手法とは異なります。エージェント開発においては、**「エージェントに必要な前提コンテキストを過不足なく与え、エージェント自身の推論ループのブレを減らす」** プロンプティングが重視されます。

## 💡 エージェント向けプロンプト設計 4原則
エージェントに指示を与える（または Skill のプロンプトを書く）際は、以下の4原則を意識します。

1. **コンテキスト (Context)**: 「今どのファイル、どのモジュールを対象としているか」を明確にする（例: `hands-on/s2-basics/calc.py を対象に...`）。
2. **目標 (Objective)**: 「何を行うべきか」を具体的に定義する。
3. **制約 (Constraints)**: 「何をしてはいけないか、何に準拠すべきか」（例: `pytest を使うこと`、`print ではなく logging を使うこと`）。
4. **出力形式 (Output format)**: 「どう見せてほしいか」（例: `正常系・異常系に分けてチェックボックス形式でテスト結果を出して`）。

## 📂 AGENTS.md の役割と配置
エージェントに対して「毎回同じプロジェクトの制約事項」を伝えるために、**`AGENTS.md` (コンテキストファイル)** を利用します。

### 配置ルール
*   **プロジェクトローカル**: プロジェクトルート直下に `AGENTS.md` を配置します。エージェントはそのディレクトリで起動した際、自動的にこのファイルを読み込んで記憶（システムプロンプト）に統合します。
*   **グローバル（デフォルトルール）**: `~/.gemini/config/AGENTS.md` に配置することで、プロジェクトをまたいだ個人用の共通開発ルール（例: "日本語で返答して"、"不要なコメントは残さないで"）を永続化できます。

### 推奨される `AGENTS.md` のテンプレート
```markdown
# プロジェクト名

プロジェクトの簡単な概要。

## 🛠️ 技術スタック
- 言語: Python 3.11
- フレームワーク: FastAPI
- テスト: pytest

## ⚙️ 開発・設計ルール
- 関数には必ず型ヒントと docstring を付けること
- 例外処理はキャッチ＆スルーせず、適切にログ出力すること
- 外部APIへの接続は必ず環境変数経由で行うこと

## 🧪 テスト・確認コマンド
- 単体テスト: `pytest tests/`
- 静的解析: `ruff check`
```

# Sub-agents (専門・サブエージェント)

## 📝 概要
Sub-agents（サブエージェント）とは、メインのエージェントから呼び出される**独立したコンテキスト（会話履歴）と特定の役割を持った子エージェント**です。

複雑なタスクをこなす際、単一のエージェントですべてを処理しようとすると、会話履歴（コンテキストウィンドウ）が肥大化し、コストの増加やモデルの指示忘れが発生します。Sub-agents を利用することで、「テスト担当」「ドキュメント担当」「コードレビュー担当」などのように専門特化した人格にタスクを委譲し、メインの会話履歴を温存しながら並列で効率的にタスクを完了させることができます。

## ⚙️ Skills と Sub-agents の違い

| 観点 | [[Agent Skills|Agent Skills]] | Sub-agents |
|---|---|---|
| **コンテキスト** | メインと同じ会話履歴を消費する | **完全に独立した新規の会話履歴** |
| **主な用途** | プロンプトの共通化・定型処理 | 並列処理・巨大コンテキストの隔離・専門的な役割分担 |
| **履歴の節約** | 指示が多いため履歴を消費しやすい | メイン履歴を消費せず、要約結果だけを親に戻す |

## 🚀 委譲の設計パターン
1. **並列処理 (Parallel Forking)**: メインエージェントが「実装」「テスト」「ドキュメント」を同時に3つの Sub-agents に割り振り、それぞれ並列で作業を実行させます。
2. **監査・レビュー (Review Loop)**: メインエージェントがコードを実装した後、「セキュリティ監査エージェント」にコードを渡し、その監査結果を受け取ってから修正を行います。
3. **巨大ファイル読込 (Context Insulation)**: 数万行のログファイルやドキュメントを読み込ませる際、専用の Sub-agent に読ませて必要な情報だけを要約してメインエージェントに持ち帰らせることで、メイン会話のトークン消費を抑えます。

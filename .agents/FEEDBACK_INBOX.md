# AI Feedback Inbox

AIの操作や出力に関するユーザーからの指摘事項を一時的に保管するファイル。
ここに蓄積された指摘は定期的に見直され、汎用的なルールとして `AGENTS.md` や `DESIGN_RULES.md` に昇華される。

## 2026-07-08
- **指摘内容**: Marpスライドのレイアウトチェックにおいて、コードブロックを含むスライド（S4 Slide 13）の表示あふれを静的解析ツールのみで検知できなかった。
- **原因と分析**: 行数だけをカウントする簡易的なPythonスクリプトで判定していたため、コードブロック特有の上下余白やフォントサイズの大きさが考慮されていなかった。
- **将来のルール化案**: レイアウトチェック用スクリプトを改善し、```` などのコードブロックが含まれる場合は1行あたりの重みを大きく計算する、もしくは静的解析の限界をユーザーに提示し、目視確認をより強く推奨するフローをルール化する。

## 2026-07-08 (2)
- **指摘内容**: ハンズオン用のスライド内で、実際にはJavaScript（Node.js）を使用しているにも関わらず、目標やまとめのスライドで「Python（FastMCP）」と誤って記載していた。
- **原因と分析**: ハンズオンの後半のコード実装（JavaScript）のコンテキストを十分に確認せず、世間的な流行語や一般的な説明文（FastMCPなど）を流用してスライド冒頭の「ゴール」を作成してしまった。資料内の前後関係の不一致（フロントとバックエンドで言語が異なる等）に気づけなかった。
- **将来のルール化案**: スライド作成・編集時には、**「スライド内の説明（特にゴールやまとめ）」と「実際のハンズオン・デモの内容」の間に矛盾がないか（言語、ツール、バージョンなど）**をセルフレビューする項目を追加する。

## 2026-07-09
- 指摘内容: index.js内のコードスニペットの改行整形をスライド（s4-mcp.md）にも反映した際、`DESIGN_RULES.md` で義務付けられている `npm run test:slides` の実行を怠り、スライド13が行数超過で表示崩れを起こした。
- 原因と分析: 「コードを整形して」という単発の指示をスライド編集タスクとして扱ったが、編集後に必須のLintコマンドを実行するステップを踏まなかった。ルール自体は既に存在していたが、実行が漏れた。
- 将来のルール化案: スライドMarkdown（`[0-9]*/*.md`）へのEdit/Write実行後は、応答を返す前に必ず `npm run test:slides` を実行することをタスクの一部として組み込む（チェックリスト化）。

## 2026-07-09 (2)
- 指摘内容: 行数超過の修正時、コードブロックを1行に詰め込む圧縮を行ったため改行が見づらくなった。
- 原因と分析: `check_layout.py` の「コードブロック含み14行まで」という一律の行数制限をパスさせることを優先し、可読性より圧縮を優先してしまった。ルール上「テキスト圧縮やスライド分割」としか書かれておらず、圧縮より分割を優先すべきという順序が明記されていなかった。
- 対応: `DESIGN_RULES.md` に「過度な一行詰め込みを既定手段にせず、まずスライド分割を検討する」旨を追記済み。

## 2026-07-09 (3)
- 指摘内容: スライド統合時にLinter通過だけを目的に `font-size: 0.85em` を適用したが、実際には文字が小さすぎて見づらかった。
- 原因と分析: `lint:visual`（Playwright）は「枠からのはみ出し」しか検知しておらず、文字サイズや可読性は一切チェックしていない。それにもかかわらず、スクリーンショットで目視確認せずLinterのPassのみで完了と判断した。
- 将来のルール化案: フォントサイズを縮小するスタイル調整（`<style scoped>`でのfont-size指定など）を行った場合は、Lintのpassに関わらず、必ずビルド後のスライド画像を目視確認するステップを追加する。今回は標準サイズ(1em)でも実際は収まることが判明したため、静的解析の行数目安のみが引っかかる場合は`<!-- ignore-layout -->`で理由を明記した上で除外する運用とした。

## 2026-07-09 (4)
- **指摘内容**: 特定のMCPツール（pokemon/get_pokemon_info）の実行時にエラー（invalid character 'u' looking for beginning of value）が発生した。また、その際、AIが自律的にWeb検索ツール（search_web）を使用して情報を補完・代替した。
- **原因と分析**: 
  1. `pokemon-mcp-server` の `index.js` 内で `console.log(res.data);` が実行され、`undefined` という非JSON文字列が標準出力（Stdio JSON-RPC 通信路）に出力されたため、パースエラーが発生した。
  2. ツールエラーによってタスクが未達成になることを防ぐため、自律的にフォールバック（Web検索）を選択した。しかし、ユーザー側がツールの動作検証を行っている場合、このフォールバックは「不具合の隠蔽」や「意図しない検索ツールの利用」になってしまう。
  3. エラー発生後、`index.js` の `console.log` を修正したが、Antigravity CLI 側の MCP 接続プールにエラー状態の接続がキャッシュされているため、セッションを再起動しないと再接続できない。
- **将来のルール化案**: 特定のツールの検証や利用を目的としている指示に対して、ツール実行に失敗した場合は、他のツールへ勝手にフォールバックせず、エラー状況をそのまま正直にユーザーに報告すること。

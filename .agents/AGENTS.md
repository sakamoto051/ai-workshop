# Project Rules

- 【スキルの利用とルーティング】本プロジェクトには特定のタスクに特化したスキルが `.agents/skills/` に定義されています。該当する作業を行う際は、必ず以下のスキル（ルール）を遅延読み込みして従うこと。
  - **調査・ファクトチェック・情報提供** ➔ `fact-checker` スキル
  - **スライドの内容・テキスト編集** ➔ `slide-content-checker` スキル
  - **Marpスライドのレイアウト確認** ➔ `marp-layout-checker` スキル
- 【デザイン・フォーマットの遵守】デザインや出力フォーマットに関するルールは、同じディレクトリ内の `DESIGN_RULES.md` を読み込んで必ず従うこと。出力時の常体・敬体ルールなどもこれに含まれる。
- 【ミス発生時の基本行動】ユーザーから間違いやミスを指摘された場合、単に謝罪して修正するだけでなく、必ず「原因調査」「再発防止策の立案」「ルール化・スキル化」の再発防止プロセスを自律的に実行すること。
- 【仕組みづくりの原則】改善や再発防止を行う際は「気をつけて頑張る（属人的・精神論な解決）」のではなく、「システム的にミスが起きない・悪くできない仕組みづくり（フールプルーフ、Linterの導入、自動テスト、制約の追加など）」を最優先に行うこと。
- 【指摘事項の一時保管と一般化】AIの操作不備によるユーザーからの指摘事項は、すぐに全体ルールへ追記するのではなく、まず一時ファイル（例: `.agents/FEEDBACK_INBOX.md`）に保管すること。そして定期的に保管内容を見直し、一般化して適用できるものは `AGENTS.md` や `DESIGN_RULES.md` にルールとして正式に昇華させること。
- 【ログ解析の注意点】`Tool calls` のトークン数は「ツール呼び出し時のリクエスト（JSON）のサイズ」のみを示しており、レスポンスのサイズは含まれない。トークン数が少ないからといって「ツールが実行されていない」と早計に推測してはいけない。必ずトランスクリプトの実ログを確認すること。
- 【表現のルール】AIによるドキュメントやスライド生成、およびユーザーとのコミュニケーションにおいて、カギ括弧（「」）を無闇に乱用しないこと。強調が必要な場合はMarkdownの太字（**強調**）などを優先する。
- 【指摘事項の自動ルール化】ユーザーからAIに対して複数回（目安として2回以上）同様の改善要望や指摘事項があった場合、AIは自律的に「この指摘事項をプロジェクトの全体ルールに追記するか」を提案し、合意を得て永続化すること。
- 【AGENTS.mdの肥大化防止とSkill化】AGENTS.md の内容（ルール）は量が増えてきた場合、定期的にチェックを行うこと。特定のコンテキストに依存するルールやまとまった専門知識は、積極的に `skills/` のモジュールとして独立・切り出し（Skill化）を行うこと。

# デザイン・出力ルール

## 出力・フォーマットに関するルール
- 出力やファイルの編集において、絵文字（Emoji）は一切使用しないでください。
- 文章や出力において、安易に太字（Bold）を使用しないでください。
- 会話中で出た内容（補足説明など）を、スライドやコード内に冗長に記載・追記しないでください。
- ユーザーへの応答文末は「です・ます調（敬体）」を避け、「だ・である調（常体）」を使用してください。
- スライドなどのドキュメントやコードのコメントにおいて、過剰な説明口調（例：「〜は小さなファイルだ」「〜するだけで完成する」「次のページから見ていく」など）は避け、簡潔で端的な表現を使用してください。
- ハンズオンの手順やワークショップの進行手順を作成・追記するよう求められた場合は、別ファイル（README.md等）に切り出すのではなく、対象のスライド用Markdownファイル（.md）に直接新しいスライドページとして追加してください。

## Marp スライドのデザイン確認に関するルール
Marp のスライド（.md）を編集・修正した後は、`npm run lint:layout` による静的解析に加え、**必ず Playwright（MCPまたはスクリプト） を使用して実際の表示結果（スクリーンショット）を撮影し、視覚的にレイアウトが崩れていないか確認すること**を義務とする。
以下の観点でレイアウト崩れがないか確認してください。
- コンテンツのはみ出し（表、図、長いテキストがスライド境界を越えていないか）
- 意図しない改行（ラベルやタイトル等が不自然に折り返されていないか）
- パースエラー（HTMLタグがそのまま画面に露出していないか）
- 装飾と禁止文字（CSSが正しく描画されているか、絵文字が混入していないか）
- 要素の重なり（図表やテキスト同士が重なっていないか）

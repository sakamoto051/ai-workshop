# Marp Layout Checker

Marp スライドを編集した後に呼び出し、HTML 表示時のレイアウト崩れを検出・報告するスキル。

## Playwright MCP を使ったスクリーンショットチェック（推奨）

Marp サーバー（`http://localhost:8080`）が起動している状態で、Playwright MCP を使って各スライドのスクリーンショットを撮影し、レイアウト崩れを目視確認する。

### 手順

1. **Marp サーバーが起動していることを確認**
   - `http://localhost:8080/s1-intro.md` にアクセスして一覧を確認

2. **Playwright MCP でスクリーンショット撮影**
   - `playwright_navigate` で対象 URL を開く（例: `http://localhost:8080/s1-intro.html`）
   - `playwright_screenshot` でページ全体をキャプチャ
   - スライドは Marp の矢印ナビゲーションで進める、または URL に `?p=N`（N=スライド番号）を付ける

3. **確認ポイント**
   - テーブルがスライド右端からはみ出していないか
   - コンテンツがスライド下端で切れていないか
   - 引用ブロックや箇条書きが見切れていないか

4. **崩れを発見したら**
   - スライド番号と崩れの種類をレポート
   - 修正案（テキスト短縮・スライド分割など）を提示

## チェック手順

### 1. ファイル構造チェック（静的解析）

```bash
# スライドファイルを対象に解析
TARGET_FILE="<対象の .md ファイル>"
```

以下を順番に確認する：

#### ① スライド境界（`---`）の整合性
- 各スライドが `---` で正しく区切られているか
- `---` の直前に空行があるか（Marp の仕様）
- フロントマター（`--- ... ---`）と本文の `---` が混在していないか

```bash
grep -n "^---" "$TARGET_FILE"
```

#### ② テーブルの列数チェック
横に列が多いテーブルはスライドからはみ出す危険がある。
4列以上のテーブルを抽出して警告する。

```bash
grep -n "^|" "$TARGET_FILE" | awk -F"|" '{if(NF-1 > 4) print NR": 列数="NF-1, $0}'
```

#### ③ 1スライドあたりの行数チェック
Marp のデフォルトスライドに収まる目安は **本文 15〜18 行以内**。
超過しているスライドを検出する。

```bash
python3 - <<'EOF'
import re, sys

with open("slides/s1-intro.md") as f:
    content = f.read()

slides = re.split(r'\n---\n', content)
for i, slide in enumerate(slides[1:], 1):  # フロントマター除外
    lines = [l for l in slide.strip().split('\n') if l.strip()]
    if len(lines) > 18:
        print(f"⚠️  スライド {i}: {len(lines)} 行（目安超過）")
        print(f"   先頭: {lines[0][:60]}")
EOF
```

#### ④ スライド境界の破損チェック（見出しと `---` の間に空行なし）
```bash
grep -n -A1 "^## " "$TARGET_FILE" | grep -v "^--$" | grep "^---$"
```

### 2. Marp サーバーで目視確認

Marp サーバーが起動していることを確認し、ブラウザで各スライドを開く。

```bash
# サーバー起動確認
ps aux | grep "marp" | grep -v grep

# 未起動の場合
npx @marp-team/marp-cli --server slides &
```

ブラウザで `http://localhost:8080/<ファイル名>.html` を開き、以下を目視確認：

| チェック項目 | 確認ポイント |
|---|---|
| テーブルのはみ出し | 右端が切れていないか |
| コードブロック | スライド下端で切れていないか |
| 箇条書き | 最後の項目が見切れていないか |
| 見出し | `##` がスライド冒頭に正しく表示されるか |
| 引用ブロック `>` | 複数行でも収まっているか |

### 3. 結果レポート形式

チェック完了後、以下のフォーマットで報告する：

```
## Marp レイアウトチェック結果

**対象ファイル**: slides/s1-intro.md
**チェック日時**: YYYY-MM-DD HH:MM

### ✅ 問題なし
- スライド境界: 正常
- ...

### ⚠️ 警告（目視確認推奨）
- スライド 7「三社のドキュメント...」: 18行（上限ぎりぎり）

### ❌ 要修正
- スライド 3「OpenAI が定義する...」: テーブル 5列（はみ出しの可能性）
  → 対応: 1社1枚に分割するか、列を削減する
```

## よくある崩れパターンと対処法

| パターン | 原因 | 対処法 |
|---|---|---|
| テーブルが右にはみ出る | 列数が多い / セルのテキストが長い | 列を削減 or 行方向に変換 |
| コンテンツがスライド下にはみ出る | 行数が多すぎる | スライドを2枚に分割 |
| `---` がスライド区切りにならない | 前後に空行がない | `---` の前後に空行を追加 |
| 引用 `>` が複数行で崩れる | 行数過多 | 引用を短縮 or 箇条書きに変換 |
| コードブロックが巨大 | 行数過多 | 重要部分のみ抜粋 or 別スライドに |

## トリガー

このスキルは以下のタイミングで使う：
- Marp スライドを編集した直後
- 「レイアウト確認して」「はみ出ていないかチェック」と言われたとき
- テーブルや引用ブロックを追加・変更したとき

# PR Draft Skill

## 手順

1. `git diff --staged` を試みる。出力が空なら、カレントの `sample.diff` を読む。
2. 変更内容を解釈する。
3. 次の構成で本文を書く:

```
## Why
- 変更の動機

## What
- 主要な変更点

## Test plan
- [ ] 確認項目
```

4. ユーザに見せる。長さは 300〜500 字程度。冗長禁止。

## 注意

- 推測で機能名を作らない。差分から読み取れる範囲で書く。
- 既存の規約に反する書き方は避ける。

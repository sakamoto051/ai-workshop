# S2 ハンズオン: コンテキストと設定の実践

本ハンズオンでは、設定ファイル（`AGENTS.md`）を用いたコンテキスト管理とプロンプト設計の効果を実践し、トークン量やAIの振る舞いの変化を確認します。

測定結果は [result_sheet.md](result_sheet.md) に記録してください。

---

## 準備と初期状態の確認

1. 対象のファイル `calc.py` と、ルール確認用のスクリプト `verify_rules.py` が存在することを確認します。
2. 本ハンズオンでは、以下の「社内コーディング規約」が存在すると仮定します。
   - **規約①**: テストフレームワークは `unittest` を使用すること（`pytest` は使用禁止）。
   - **規約②**: 計算の処理中には直接 `print` を使用せず、標準の `logging` モジュールでデバッグログを出力すること。

---

## フェーズ 1: 読み込み設定の確認

AIエージェント起動時、どの設定ファイルがコンテキストとして自動で読み込まれているかを確認します。

1. カレントディレクトリ（プロジェクト固有）に `.agents` ディレクトリを作成し、その中に `AGENTS.md` を作成します。
   ```bash
   mkdir -p .agents
   touch .agents/AGENTS.md
   ```
2. `.agents/AGENTS.md` に簡単な挨拶ルールを記述します。
   ```markdown
   # AIの振る舞い
   - 返答の最後には必ず「ルール確認ヨシ！」とつけること。
   ```
3. AIエージェントを立ち上げ、適当な質問（例: 「こんにちは！」）を入力します。
4. エージェントがプロジェクト固有の `AGENTS.md` を読み込み、指定した語尾で返答することを確認します。

---

## フェーズ 2: ルールの適用検証

次に、実用的な設定ファイルを記述し、コーディング規約が正しく適用されるかを確認します。

1. 先ほど作成した `.agents/AGENTS.md` の内容を、以下の実用的なルールに書き換えます。
   ```markdown
   # Calc プロジェクト
   シンプルな CLI 電卓。

   ## コーディング規約
   - テストフレームワークは `unittest` を使用すること（`pytest` は使用禁止）
   - 計算の処理中に `print` を直接使用せず、Python標準の `logging` モジュールでデバッグログを出力すること

   ## 開発用コマンド
   - テスト実行: `python3 -m unittest discover -s tests`
   ```
2. 新しいチャットセッションを開始し、エージェントに対し、以下のように機能追加とテスト作成を依頼します。
   ```
   calc.py の各計算処理を関数に分割し、それぞれにデバッグログを出力するようにしてください。また、テストコードを追加してください。
   ```
3. エージェントが実行完了した後、以下のコマンドで規約が満たされているか検証します。
   ```bash
   python3 verify_rules.py
   ```
   すべて `[PASS]` になることを確認します。
4. エージェントの出力から**入力トークン数**を確認し、[result_sheet.md](result_sheet.md) の「フェーズ 2」の欄に記入します。
5. 終わったら、`calc.py` と `tests/` ディレクトリを元の状態に戻します（`git checkout calc.py` など）。

---

## フェーズ 3: ファイル切り出しとトークン量

`AGENTS.md` が肥大化すると毎回の入力トークン数を圧迫します。詳細な規約を別ファイルに切り出し、トークン量の変化を確認します。

1. 詳細な規約を別ファイルに移動します。
   ```bash
   mkdir -p docs
   ```
   `docs/coding-rules.md` を作成し、`.agents/AGENTS.md` に書いていた「コーディング規約」と「開発用コマンド」の内容をこちらへ移動します。
2. `.agents/AGENTS.md` は以下のように短く書き換え、別ファイルへのリンクのみを残します。
   ```markdown
   # Calc プロジェクト
   シンプルな CLI 電卓。

   詳細なコーディング規約と開発コマンドは [docs/coding-rules.md](docs/coding-rules.md) を参照すること。
   ```
3. 新しいチャットセッションを開始し、再度フェーズ 2 と同じ依頼を実行します。
4. 以下の2点を確認します。
   - エージェントが**自律的に別ファイル（`docs/coding-rules.md`）を読みに行く動作**を行ってからコーディングを開始したか
   - **初回の入力トークン数（初期プロンプトのトークン数）が減少しているか**
5. 確認したトークン数を [result_sheet.md](result_sheet.md) の「フェーズ 3」の欄に記入し、フェーズ 2 と比較します。

## 7. Gitブランチ戦略・レビュー・リリースプロセスの自動化
- Conventional CommitsとSemantic Versioningの完全自動化:
  - コミットメッセージからセマンティックバージョニング（SemVer）を自動計算し、リリースPRの作成、CHANGELOG.mdの生成、GitHub Releasesの発行を自動化するツール（Release PleaseやSemantic Release）を利用する。
- コードレビューのチェックリスト（必須項目）:
  - セキュリティ: SQLインジェクション、XSS、認可バイパスのリスクはないか。
  - パフォーマンス: ループ内でのDBアクセス（N+1）や、不必要な再レンダリングはないか。
  - 設計: 単一責任の原則（SRP）、オープン・クローズドの原則（OCP）に違反していないか。
  - テスト: 正常系だけでなく、エッジケースや異常系のテストが網羅されているか。
- デプロイとロールバック:
  - すべてのデプロイメントはカナリアリリースで行う。最初の1%のトラフィックを新バージョンに流し、Datadog等のメトリクス（エラーレート、レイテンシ）を5分間監視。異常がなければ段階的に100%まで拡張し、異常を検知した瞬間、自動で旧バージョンへルーティングを戻す（Automated Canary Analysis）。
